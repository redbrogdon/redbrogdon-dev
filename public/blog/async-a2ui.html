Speeding up generative UI with async A2UI

August 13, 2026 · 7 min read · Generative UI, A2UI, Flutter
Originally published on The Flutter Blog on Medium ↗.

One of the central promises of Generative UI (GenUI) is that interfaces are no longer statically bound to design-time assumptions. Instead, an autonomous agent can compose layouts dynamically based on runtime context, user intent, and live system state. But this flexibility comes with an unavoidable penalty: startup latency.

When a user launches an application or navigates to a new view, waiting 2 to 4 seconds for an LLM to digest the prompt, invoke tool calls, generate structured JSON, and stream the UI definition can ruin the experience. To build production-grade agentic experiences, we need architectures that eliminate cold-start lag without giving up generative adaptability.

The Cold Start Dilemma

In traditional GenUI implementations, the client application sends a request to an agent, and the agent constructs an A2UI message payload. That pipeline involves multiple network hops, prompt processing, model inference, and client-side widget deserialization. If this happens synchronously on the critical path, the user stares at a loading indicator.

"The best generative interface is the one that's already rendered before the user asks for it."

To address this, we developed an asynchronous pre-generation and caching pattern within the A2UI framework. Rather than generating interfaces reactively on button taps, the agentic runtime predicts probable workflows and synthesizes candidate A2UI payloads ahead of time.

Case Study: The Commis Assistant

We tested this pattern in Commis, an intelligent assistant application designed for commercial kitchen environments where chefs need instant hands-free guidance during food prep shifts.

In Commis, prep lists, recipe alterations, and inventory adjustments require rich UI components: timers, ingredient check-lists, and temperature gauges. By running speculative agent passes during natural pauses in workflow, Commis pre-generates the upcoming step's A2UI layout and stores it in a fast local cache. 

// Example A2UI Async Pre-cache Strategy
class A2UICacheManager {
  final Map<String, A2UIMessage> _pregeneratedViews = {};

  Future<void> prefetchProbableNextStep(AgentSession session) async {
    final nextIntent = await session.predictNextUserIntent();
    final cachedPayload = await session.agent.generateA2UIPayload(nextIntent);
    _pregeneratedViews[nextIntent.identifier] = cachedPayload;
  }

  Widget resolveView(String intentId, WidgetCatalog catalog) {
    if (_pregeneratedViews.containsKey(intentId)) {
      // Instant render: zero model latency
      return catalog.buildFromA2UI(_pregeneratedViews.remove(intentId)!);
    }
    // Fallback to streaming live generation
    return LiveGenUIStreamView(intentId: intentId, catalog: catalog);
  }
}

Streaming Incremental Updates

Pre-generating UI doesn't mean the interface must remain static once loaded. The core strength of the A2UI protocol is its event-driven patch model. A cached baseline widget tree can mount instantaneously (0ms perceived latency), after which background agent workers stream lightweight delta patches to update live quantities, status indicators, and timers in real-time.

Conclusion

Generative UI does not have to mean slow UI. By treating interface generation as an asynchronous, speculatively scheduled process rather than a synchronous blocker, developers can deliver apps that feel as responsive as hand-crafted native interfaces while preserving the adaptive intelligence of agentic systems.
